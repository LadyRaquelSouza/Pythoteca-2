# CATALOG-001.1 — Contrato de metadados

Base 84ad719, ADR-001, SECURITY-001 T05/T12 e PRODUCT-NEXT. Library atual: modules/index.json schema_version 2, 45 entradas, catalog/index.json schema_version 1, três entradas incluindo aula99 demonstrativa. Caminhos observados modules/aula101.json e catalog/aula01.json. Disciplinas v2: arquitetura, portugol, java, sistemas_operacionais, ti, modelagem_dados. v1 mapeado a python. Preservar IDs e ordem editorial; não fixar quantidade de aulas no leitor.

Objetivo: domínio Java puro no reader/catalog, independente de Android, rede e UI. Primeiro incremento recebe metadados já decodificados, não aceita texto JSON ainda; validar tipos exatos, campos, IDs, tamanhos, hashes, disciplina, unicidade global e limites de quantidade. Derivar caminhos de esquema/ID, nunca aceitar URL ou caminho de entrada. Excluir aula99 v1 explicitamente da listagem de estudos, mas validar antes de excluir. Verificar bytes e SHA-256 de aula contra metadados; isso não autentica o catálogo. Listas imutáveis. Limites candidatos 2048 entradas totais, 4 MiB por aula, 240 caracteres título, 512 subtítulo; ajustar por evidência e versionar se necessário. Não fixar intervalos de IDs por disciplina. Sem nova dependência.

Alternativas: parser Android org.json (não usado nesta etapa; verificar duplicatas e coerção na próxima); biblioteca JSON externa (adiada até requisitos de parser estrito). Não expor metadados não autenticados à UI. Próximo: decoder estrito com limites de bytes/profundidade/duplicatas/UTF-8, assinatura sobre bytes exatos, manifesto com geração e rollback, chave confiável, transporte HTTPS fixo e cache atômico. Não há autorização para publicação de chave privada ou mudança Library.

Aceite: testes JVM positivos v1/v2, colisões, traversal, tipo inválido, hash/tamanho, limites, imutabilidade, demo e ordem; regressão Android. Reversão: remover domínio e testes sem efeitos em dados existentes. Nenhum download, armazenamento, parser de aulas, assinatura ou rede nesta fase. Sem uso real até gates.
