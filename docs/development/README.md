# Diário de desenvolvimento

Memória operacional versionada da Pythoteca. Diferente do diário pedagógico Pythoteca por dentro, este registro permite retomar o trabalho sem depender de conversas anteriores.

## Protocolo obrigatório de continuidade

Antes de iniciar uma etapa: ler STATUS.md, ADRs, modelo de ameaças e PRs abertos; conferir main e CI reais. Registrar objetivo, hipótese, alternativas, escopo aprovado, critérios de aceite e plano de reversão. Não tratar propostas como decisões.

Durante: registrar mudanças, commits, experimentos, resultados negativos, hipóteses descartadas, decisões e desvios. Atualizar STATUS.md em cada ponto de parada, inclusive antes de aguardar CI. Não registrar segredos, dados pessoais ou materiais privados.

Depois: registrar evidências, commit testado, execução e tentativa, artefatos, limitações, decisão de merge e próximo passo. Não apagar falhas anteriores. Corrigir afirmações antigas com notas explícitas. Distinguir planejado, aprovado, implementado, testado, bloqueado e concluído.

Cada PR deve incluir atualização do diário ou justificar por que não precisa. Registros devem permanecer no repositório; a Library recebe explicações pedagógicas, não substitui a memória operacional.
